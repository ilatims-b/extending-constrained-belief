# Extending Constrained Belief

A framework for training Transformer models on synthetic data generated by
Epsilon Machines (Hidden Markov Models) and analyzing their ability to learn
statistical dependencies, focused on the Mess3 family of processes
(`Mess3`, `Linear_Mess3`).

## Overview

This project enables:
1. **Process generation**: Defining stochastic processes (e.g. `Mess3`,
   `Linear_Mess3`, `RRXOR`, `ZeroOneR`) via HMMs.
2. **Transformer training**: Training PyTorch/`transformer_lens` models to
   predict these processes.
3. **Analysis**: Measuring performance with vectorized KL-divergence
   metrics against empirical N-gram statistics and ground-truth Markov
   states, plus simplex-projection (belief-state) MSE.

## Installation

From the repo root:

```bash
pip install -e .
```

This installs the `epsilon_transformers` package (editable, so local edits
take effect immediately) along with its dependencies (`torch`,
`transformer_lens`, `wandb`, `datashader`, `jaxtyping`, `pydantic`,
`scikit-learn`, `pandas`, `matplotlib`, `tqdm`, `fire`, `python-dotenv`).

## Usage

### Training

`train_mess_3_linear.py` is a small, ready-to-run training entry point:

```bash
cd epsilon_transformers
python3 train_mess_3_linear.py
```

It builds a `TrainConfig` in code (model, optimizer, dataset, persistence,
logging, and analysis settings) and calls `train_model(config)`. Edit the
config objects at the top of the file to change scale, process, or
hyperparameters; flip `USE_LINEAR` to switch between `Linear_Mess3` and
plain `Mess3`. `wandb` logging is off by default so it runs offline.

The training pipeline automatically:
- Builds empirical N-gram statistics from the training set (GPU-accelerated).
- Trains the model on the synthetic process.
- Evaluates KL-divergence and simplex-MSE metrics periodically, and
  checkpoints the model.

Output (checkpoints, metrics CSVs, n-gram tables) is written under
`epsilon_transformers/models/<run_name>/`.

### Training on Kaggle

`eps_trans_kaggle.ipynb` is a Kaggle-ready notebook (clones this repo,
installs it, and trains) — see [Kaggle Notebook](#kaggle-notebook) below.
**Training with the report-models config (below) on a Kaggle T4 GPU takes
around 9 hours** for the full `num_tokens=2_000_000_000` run.

## Report-Models Training Configuration

The reference training runs this project's earlier development produced
were all trained with the same model architecture and optimizer/dataset
settings; only the process being learned (`process` / `process_params` in
the dataset config) changed between them.

**Architecture (identical across every reference run):**

```python
model_config = RawModelConfig(
    d_vocab=3,
    d_model=64,
    n_ctx=10,
    d_head=8,
    n_head=2,
    d_mlp=256,
    n_layers=1,      # 2 for the layer-comparison runs, see below
)
```

**Optimizer, dataset structure, and analysis (the 5 single-layer Mess3
sweep runs — `0.02_0.9`, `0.15_0.6`, `0.25_0.5`, `stage_0.1_0.7`,
`stage_0.28_0.85`):**

```python
optimizer_config = OptimizerConfig(
    optimizer_type="adam",
    learning_rate=1e-4,
    weight_decay=0,
)

dataset_config = ProcessDatasetConfig(
    process="Mess3",                # only this + process_params varied
    process_params={"x": ..., "a": ...},
    batch_size=128,
    sequence_length=10,
    num_tokens=2_000_000_000,       # 0.15_0.6 used 3.6e9
    test_split=0.0005,
    test_batch_size=1_000_000,
    chunk_size=2048,
)

analysis_config = AnalysisConfig(
    analysis_batch_size=100,
    ngram_analysis=NGramAnalysisConfig(enabled=False),
    markov_kl_analysis=MarkovKLAnalysisConfig(enabled=True, return_per_position=False),
    simplex_analysis=SimplexAnalysisConfig(
        enabled=True,
        hook_point="blocks.0.hook_resid_post",
    ),
)

seed = 42
```

`checkpoint_every_n_tokens` (in `PersistanceConfig`) varied per run
(300k–3M) and isn't architecturally significant.

**The 2-layer comparison runs** (`Mess3` and `Linear_Mess3`, both at
`x=0.5, a=0.2`) used the same architecture with `n_layers=2` and SGD
instead of Adam:

```python
model_config = RawModelConfig(d_vocab=3, d_model=64, n_ctx=10, d_head=8, n_head=2, d_mlp=256, n_layers=2)
optimizer_config = OptimizerConfig(optimizer_type="sgd", learning_rate=1e-2, weight_decay=0)
```
with the same dataset structure (`batch_size=128, sequence_length=10, num_tokens=2e9, chunk_size=2048`).

`train_mess_3_linear.py` uses a smaller, faster version of this config by
default (for quick local iteration); scale it up to the settings above to
reproduce a reference-quality run.

## Key Components

- **`epsilon_transformers/process`**: HMM process definitions
  (`Process.py`, `processes.py`) and GPU-batched dataset generation
  (`dataset.py`), plus the Mixed State Presentation tree
  (`MixedStateTree.py`) used to compute belief states and myopic entropy.
- **`epsilon_transformers/training`**: Training loop (`train.py`) and
  Pydantic config schemas (`training/configs/`).
- **`epsilon_transformers/analysis`**: Vectorized analyzers for N-gram KL
  divergence (`ngram_analysis.py`), Markov KL divergence
  (`kl_analysis.py`), and simplex-projection MSE (`simplex_analysis.py`).
- **`epsilon_transformers/visualization`**: Plotting/graph helpers for
  belief-state simplexes and process graphs.
- **`epsilon_transformers/persistence.py`**: Checkpoint, config, and
  metrics-CSV I/O (`Persister`).

## Metrics

- **test/loss**: Cross-entropy loss.
- **test/relative_loss**: Ratio of loss to the theoretical myopic entropy.
- **test/kl_div_ngram_N**: KL divergence between model predictions and
  empirical N-gram frequencies.
- **test/kl_div_markov**: KL divergence between model predictions and the
  true hidden Markov process.
- **test/simplex_mse**: MSE between the model's residual-stream projection
  and the ground-truth belief-state simplex.

## Kaggle Notebook

`eps_trans_kaggle.ipynb` clones this repo, installs it, and runs a
training job — for training at reference scale on a GPU you don't have
locally (e.g. Kaggle's free T4). **Update the repo URL in its clone cell**
to point at wherever this repo actually lives before running it.

Before running it:
- Set `GITHUB_TOKEN` as a Kaggle secret if the repo isn't public (used only
  for the `git clone` step — the notebook doesn't hardcode one).
- Set `WANDB_API_KEY` as a Kaggle secret, or leave `logging_config.wandb`
  set to `False` to run without wandb.
- Edit the `dataset_config` cell to pick the process and `x`/`a` you want;
  everything else matches the
  [report-models config](#report-models-training-configuration) above by
  default.

At the `num_tokens=2_000_000_000` scale used for the reference runs, this
takes **around 9 hours on a Kaggle T4 GPU**.

## Notes

- If `epsilon_transformers` is also installed (editably) from another
  checkout in the same Python environment, installing it from here will
  point that environment's `epsilon_transformers` at this repo instead —
  pip treats it as the same package name, so the most recent
  `pip install -e .` wins. `train_mess_3_linear.py` also inserts this
  repo's root onto `sys.path` at runtime as a belt-and-suspenders guard
  against that ambiguity.
